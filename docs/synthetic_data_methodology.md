# SentimentLab AI: Synthetic Review Generation Methodology

**Project:** Academic Mini-Project P4: Generative vs Discriminative Sentiment Analysis Laboratory  
**Document:** Synthetic Review Generation & Validation Protocol  
**Version:** 1.0  

---

## 1. Objective & Academic Substitution Disclosure

In SentimentLab AI, we examine **Research Question 3**: *Does augmenting a training dataset with 500 validated synthetic customer reviews generated by an LLM improve out-of-sample generalization of discriminative models (Experiment B vs Experiment A), or does it introduce distribution shift / synthetic artifacts?*

### 1.1 Academic Provider Substitution Notice
The academic syllabus suggests GPT-based review generation. **Google Gemini** (`gemini-1.5-flash`) is implemented as the primary generation engine due to open free-tier API quotas.
- **Model Identity:** Google Gemini (`gemini-1.5-flash`).
- **No GPT Claim:** Synthetic reviews are explicitly tagged with `"source": "synthetic_gemini"` and `"generation_model": "gemini-1.5-flash"`. We never misattribute Gemini generations to OpenAI/GPT.
- **Provider Abstraction:** The generation orchestrator (`src/llm/synthetic_review_generator.py`) implements `BaseSyntheticGeneratorProvider`, allowing seamless plug-in of OpenAI GPT models if API keys are configured.

## 2. Target Dataset Composition & Aspect Diversity

The target synthetic dataset consists of **exactly 500 unique, validated customer reviews**:

| Sentiment Class | Target Label | Target Review Count | Target Percentage |
| :--- | :---: | :---: | :---: |
| **Negative** | `0` | **167** | 33.4% |
| **Neutral** | `1` | **167** | 33.4% |
| **Positive** | `2` | **166** | 33.2% |
| **Total** | — | **500** | 100.0% |

### 2.1 Thematic & Aspect Diversity
To prevent repetitive template-based text, prompts cycle through 9 diverse customer experience dimensions:
1. *Food quality, taste, freshness, and menu variety.*
2. *Waitstaff service, attentiveness, and ordering speed.*
3. *Pricing, portion size, and perceived value for money.*
4. *Ambiance, seating comfort, noise levels, and lighting.*
5. *Wait times, queue management, and reservation handling.*
6. *Cleanliness, hygiene, kitchen visibility, and restrooms.*
7. *Takeout, food packaging, and delivery promptness.*
8. *Mixed experiences:* exceptional food but frustrating service or loud environment.
9. *Mixed experiences:* friendly welcoming staff but bland disappointing food.

## 3. Strict Multi-Stage Validation Pipeline

Every candidate review produced by the generative model passes through `SyntheticReviewValidator`:

```
Candidate LLM Review
         │
         ▼
[Stage 1: Structural Integrity] ──────► Non-empty? 25 <= char_len <= 2500?
         │
         ▼
[Stage 2: Placeholder Guard]   ──────► Contains "[Restaurant]", "<Dish>"? ──► REJECT
         │
         ▼
[Stage 3: Class & Label Agreement] ───► label in [0,1,2] and matches sentiment string?
         │
         ▼
[Stage 4: Synthetic Uniqueness] ──────► Exact lowercase duplicate in synthetic pool? ──► REJECT
         │
         ▼
[Stage 5: Real Yelp Collision]  ──────► Exact collision with train/val/eval Yelp sets? ──► REJECT
         │
         ▼
[Stage 6: Heuristic Consistency] ─────► Blatant semantic contradiction? (e.g. Neg + pure praise)
         │
         ▼
    ACCEPTED RECORD (saved to synthetic_reviews.parquet)
```

Any record failing validation is recorded with its explicit failure reason in `artifacts/data/synthetic_reviews_rejected.parquet`.

## 4. API Resilience & Checkpoint Strategy

Under Google Gemini's free-tier constraints (15 requests per minute):
1. **Batching:** Reviews are generated in batches of 10 to 15 reviews per prompt.
2. **Throttling:** A mandatory 4.0-second pause is enforced between successive API requests.
3. **Exponential Backoff:** If HTTP 429 (`ResourceExhausted`) or 503 (`Unavailable`) occurs, the engine backs off with exponential delay ($2 \times \text{delay}$) plus random jitter.
4. **State Checkpointing:** After each batch, the state is persisted to `artifacts/data/checkpoint_synthetic_generation.json`. If execution is halted, running `python scripts/generate_synthetic_reviews.py` resumes from the exact count already accepted.

## 5. Quality Analysis & Audit

The quality of the final 500 accepted reviews is analyzed via `src/evaluation/synthetic_data_analyzer.py`:
- **Length Distributions:** Character and word counts (mean, median, standard deviation, minimum, maximum).
- **Exact Collision Check:** Verification of 0 overlaps with real training and test Yelp reviews.
- **Near-Duplicate Estimation:** Word-level Jaccard similarity thresholded at 0.85 to identify near-identical phrasing.
- **Class Balance Verification:** Ensuring exact target allocation (167 / 167 / 166).
- **Quality Report:** Persisted to `artifacts/results/synthetic_analysis/synthetic_quality_report.json`.
